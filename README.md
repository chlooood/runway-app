# Runway

A friendly little forecaster for a question I kept asking myself: **will I have saved enough for my exchange, and will it last?**

## Why I built this

This year my money comes in uneven pieces. I spent the summer on a co-op term in Toronto, I'm back in Vancouver for a school term with no paycheque, and in January I leave for an exchange term in Lyon. A spreadsheet could technically answer "am I okay?", but I never *want* to open a spreadsheet.

I like interactive tools because people actually use them. When you can flip between cities and watch your balance line bend, you end up exploring your money instead of avoiding it. Financial literacy isn't always taught in school, and I think a lot more people would learn it if it felt like this: something you poke at, not something you dread.

So Runway is built around my own situation. The numbers in it are synthetic, generated by a seed script, not real bank data.

## What it shows

With the demo data, I'm projected to have **$13,576** by the day I leave, against a **$7,764** goal. That goal isn't a guess: it's calculated from the Lyon budget (flights, deposit and living costs). I should finish the exchange with about **$5,942** left.

- **Goal card:** where I'll be on departure day, compared with what Lyon will cost, plus an "on track" or "short" badge.
- **Cash flow chart:** my real balance so far, a dashed projection, the goal line, and the Lyon term shaded in, including the dip on the day flights and the deposit are paid.
- **Toronto / Vancouver toggle:** switches which city's cost of living the forecast uses.
- **Spending breakdown:** where the money goes each month, by category.
- **Gentle nudges:** if I'd fall short, it suggests how much to trim from flexible spending like dining (never fixed costs like transit). If the money would run out in Lyon, it says roughly when.

## The bug that surprised me

The page took about 4 seconds to load, and I assumed the forecast math was slow. Timing it showed the API answered in under 50 ms. The real cause was Windows trying the IPv6 version of `localhost` first and waiting about 2 seconds before falling back, on every request. A one-line config change fixed it, and I learned to measure before guessing.

## How the forecast works

No machine learning, just rules you can follow. For each future day:

```
balance += any known income that day
         − daily spending: the trip's budget while I'm in Lyon,
           otherwise my average spending for the selected city
         − flights and deposit, on the first day of the trip
```

The goal is checked on departure day, but the projection keeps going until the exchange ends, so it can tell me how much I'll come home with. The trip is stored as a *planned stay* with its own budget, separate from my real expenses, so planned costs never mix with what I've actually spent. The details and limits are in the docstrings in [`services/forecast.py`](backend/app/services/forecast.py).

## Running it locally

You'll need Docker, Python 3.11+ and Node 20.19+ (or 22.12+).

**1. Start the database**

```bash
docker compose up -d --wait
```

**2. Backend** (from `backend/`)

```bash
python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env           # Windows: copy .env.example .env
alembic upgrade head
python -m scripts.seed
uvicorn app.main:app --port 8000
```

**3. Frontend** (from `frontend/`)

```bash
npm install
cp .env.example .env           # Windows: copy .env.example .env
npm run dev
```

Then open http://localhost:5173. The API docs are at http://127.0.0.1:8000/docs.

To run the tests, use `python -m pytest` from `backend/`. To start the demo data over, use `python -m scripts.seed --reset`.
